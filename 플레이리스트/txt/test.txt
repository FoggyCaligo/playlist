🔹 [ Project ]
전체적인 기획 방향

이 포트폴리오 프로젝트는 단순히 결과물을 나열하는 페이지가 아니라,
프론트엔드 개발자로서의 사고 과정과 경험을 구조적으로 전달하는 것을 목표로 기획되었다.
이를 위해 시각적 요소는 과도하게 꾸미기보다, 정보 흐름과 위계가 자연스럽게 드러나는 방향으로 설계했다.

1. 색상 설계

페이지는 전체적으로 간결하면서도 흐름이 끊기지 않는 인상을 주는 것을 목표로 했다.
색상은 단순하지만 시인성이 높아야 한다는 요구사항을 기준으로, 진한 파란색을 메인 컬러, 노란색을 포인트 컬러, 흰색을 텍스트 컬러로 구성했다.

초기에는 개발자 포트폴리오에서 흔히 사용되는 옅은 검정 계열도 고려했으나, 지나치게 익숙하고 무게감이 과하다고 판단했다.
대신 Windows PowerShell에서 느껴지는 파란색 계열의 개발자 친화적인 이미지를 차용하되, 파란색 단일 사용으로 인한 딱딱함을 완화하기 위해 따뜻한 계열의 노란색을 포인트로 추가했다.
이 조합을 통해 개발자스러움과 시각적 부담 완화라는 두 가지 목표를 동시에 충족하고자 했다.

2. 페이지 구성 및 배치 기준

이 포트폴리오 사이트는 “프론트엔드 개발자로서의 나”를 설명하는 페이지로 기능해야 한다는 전제를 두고 기획되었다.
필수 요소로는 프로젝트 경험, 평문 형태의 자기소개, 리스트 형식의 기술 스택이 있으며, 이 정보들이 서로 섞이지 않고 명확한 역할을 가지도록 페이지 단위로 분리했다.

이에 따라 페이지는 Projects / About / Skills의 세 영역으로 구성했고,
Projects 페이지를 가장 앞단에 배치해 시각적으로는 간결하지만 기능적으로 가장 밀도가 높은 화면이 먼저 노출되도록 설계했다.
또한 헤더에는 각 페이지로 이동할 수 있는 네비게이션을 배치해, 사용자가 페이지 간 이동을 자유롭게 할 수 있도록 했다.
시각적 구분선이나 외곽선을 최소화하기 위해, 레이아웃 정렬은 주로 좌우 배치를 기준으로 구성했다.

🔹 모바일 확장 설계 (PC → Mobile)

PC 기준으로 설계된 UI 구성 요소들을 모바일 환경으로 확장하면서, 기존 요소를 제거하지 않고도 모바일에서 시인성을 해치지 않는 구조를 만드는 것이 핵심 과제였다.
PC에서는 좌측 고정 요소, 네비게이션, 보조 정보 영역이 동시에 노출되어도 맥락 파악이 가능했지만, 모바일에서는 동일한 구성이 화면 점유율 증가와 정보 과밀로 이어질 수 있었다.
이에 따라 각 요소의 존재 자체를 유지하되, 표현 방식과 배치 방향을 모바일 환경에 맞게 재해석하는 방향으로 확장 구조를 설계했다.

예시 1: Navbar 요소 (가로 → 세로 전환)

PC 환경에서는 상단에서 가로로 나열된 네비게이션이 페이지 이동을 직관적으로 지원했지만, 모바일에서는 가로 나열 방식이 화면 폭을 압박하고 각 항목의 시인성을 떨어뜨렸다.
이에 따라 모바일에서는 네비게이션을 세로 나열 구조로 전환해 각 메뉴가 독립적인 클릭 영역을 가지도록 변경했다.
이 결정은 모바일 환경에서 손가락 조작 정확도를 높이고, 각 페이지 이동의 의미를 명확히 전달하기 위한 선택이었다.

예시 2: Projects 페이지 좌측 요소

Projects 페이지의 PC 레이아웃에서는 좌측 요소가 타임라인 탐색의 기준점 역할을 했고, 모바일 확장에서도 이 기준점을 유지하는 것이 중요하다고 판단했습니다.
다만 모바일 환경에서 페이지 전체가 스크롤되는 구조를 그대로 적용할 경우, 타임라인과 프로젝트 설명이 함께 움직이며 선택 맥락을 유지하기 어려운 문제가 발생했습니다.
이에 따라 모바일에서도 좌측 요소는 고정된 상태로 유지하되, 프로젝트 상세 내용을 담고 있는 카드 요소 역시 고정 레이아웃 안에 배치하고 카드 내부만 스크롤 가능하도록 구조를 분리했습니다.
이 구조를 통해 사용자는 타임라인과 선택 상태를 항상 동일한 위치에서 인지할 수 있었고, 긴 프로젝트 설명은 카드 내부 스크롤을 통해 부담 없이 탐색할 수 있도록 구성했습니다.

예시 3: About 페이지 좌측 요소

About 페이지의 PC 환경에서는 좌측에 고정된 프로필 영역이 페이지 전체 구조를 안내하는 역할을 했지만, 모바일에서는 동일한 배치가 본문 영역을 과도하게 축소시키는 문제가 있었습니다.
이 문제의 원인은 하나의 고정 영역에 묶여 있던 정보들이 모바일에서는 서로 다른 중요도와 사용 맥락을 가진다는 점을 충분히 분리하지 못한 데 있었습니다.
이에 따라 모바일에서는 프로필 영역의 정보를 역할 기준으로 재분류해, 이름과 핵심 소개 정보는 상단 콘텐츠 흐름으로 이동시키고 페이지 진입 시 바로 인지할 수 있도록 구성했습니다.
반면 연락처와 부가 정보처럼 즉각적인 탐색이 필요하지 않은 정보는 본문 흐름에서 분리해 모달 형태로 제공하도록 설계했습니다.
이 구조를 통해 모바일 화면의 시인성을 유지하면서도, 필요한 정보에는 언제든 접근할 수 있는 About 페이지의 정보 구조를 완성할 수 있었습니다.
